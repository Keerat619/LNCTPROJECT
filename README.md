# Classroom Lens

**Multimodal Attendance & Engagement Agent — local-first prototype**

Classroom Lens is a small, runnable classroom analytics prototype. It combines best-effort OpenCV detection, anonymous positional tracking, optional sound-energy sampling, a roster review workflow, and transparent rule-based teaching prompts. It includes a fictional dashboard and a 14-second synthetic test video so you can explore it without using a real classroom recording.

> **Important:** The activity index is an unvalidated combination of movement and sound, **not a measure of attention, emotion, understanding, or learning**. This prototype is not appropriate for grading or other consequential decisions and is not ready for institutional deployment.

## Quick start

### 1. Install prerequisites

- Python 3.10 or newer and a current desktop Chrome, Edge, or Firefox.
- A camera/microphone is optional. A camera requires browser permission and `localhost` or HTTPS.

From a terminal in this folder:

```bash
python -m venv .venv
```

Activate the environment:

```bash
# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

Install the two runtime dependencies:

```bash
python -m pip install -r requirements.txt
```

The installation normally needs internet access unless you already have the packages or a local wheelhouse. **After installation, the app and its bundled assets do not require network access.**

### 2. Run locally

```bash
python app.py
```

Open **http://127.0.0.1:8000** in the browser on the same computer. The default bind address is loopback so other computers cannot connect. Use `Ctrl+C` in the terminal to stop the server. Choose another port with `python app.py --port 8080`.

The hosted Arena preview is useful for the fictional dashboard and synthetic clip. It is **not** offline: sampled frames go from your browser to the preview server. To analyze private material, download this project and run it on your own computer instead.

## Try the prototype

1. The initial dashboard is **fictional demo data**, not a real class. Explore **Attendance**, **Engagement**, **Sessions**, **Settings**, and **How it works**.
2. Select **New session**. Give it a name, choose **Video file**, keep the **Frontal faces** detector and the 10-second default threshold, and confirm permission.
3. On the capture page, click **Use synthetic test clip**. The clip contains a fictional AI-generated portrait and a generated test tone, not a real recording. Optionally select **Include video audio activity** to test the sound signal. Press **Start analysis**.
4. The 14-second clip plays at normal speed. Green boxes display temporary anonymous track IDs. A consistently tracked face should cross the threshold after approximately 10 seconds. Results from this clip are labeled **SYNTHETIC CLIP**. The demo clip tests the frontal-face detector; it is not a test of the full-body detector.
5. Add a learner to the roster in **Attendance** and assign the track to the learner manually. Or leave the track anonymous. Export the roster and track observations with **Export CSV**.
6. To use your own footage, create a separate video session and choose a browser-supported local video file. For a live session, choose **Live camera** and grant permission when asked. Optional audio must also be enabled explicitly. Video analysis happens during normal playback, not as a fast offline batch. Pausing or restarting capture can create new track IDs.

A local file remains in the browser; sampled JPEG frames go to the app server. When the app is run locally, both browser and server are on the same computer. Audio is sampled by the browser, and only a numeric RMS level is sent to the server; no audio recording or transcript is saved.

## What is implemented

- **Attendance:** frontal-face Haar cascade or full-body HOG detector, greedy nearest-centre tracking, a configurable observed-presence threshold, first/last session-relative timestamps, manual roster matching, present/absent/unmarked overrides, event log and CSV export.
- **Activity trends:** aggregate movement of matched tracks, optional sound above an RMS threshold, and time-bucketed charts. The app also reports an approximate 2D eye-line tilt when two eyes are found and a longest observed stillness interval. Tilt is not gaze or full 3D head pose.
- **Teaching prompts:** deterministic, evidence-labeled rules suggest a check-in, a recap, or roster review. A prompt updates on the capture page as samples arrive. These are **not generated by an LLM** and are not a trained engagement model.
- **Local storage:** session metadata, names, track IDs, elapsed timestamps, numeric signal samples and settings are stored in `data/sessions.json`. Frames, videos, audio recordings, transcripts, biometric embeddings and face identities are not stored by the app. Temporary boxes exist only in server memory while tracking.
- **Tests:** `python -m unittest discover -s tests -v`. API assertions use a fake detector; a separate test runs the actual OpenCV detector on the bundled synthetic clip when WebM decoding is available.

### Activity formula

For each sampled moment, the illustrative index is:

```text
100 × (0.65 × fraction of matched tracks whose centers moved
       + 0.35 × sound-active indicator)
```

When either component is unavailable, weights are normalized over the available component. Timeline points and summary values average available samples. Sound-active means short-window RMS is at or above the configurable threshold; it is not speech detection. Eye-line tilt and stillness are displayed separately and do not affect this score. Camera shake, background noise, framing, disability, occlusion and quiet work can change the signals without indicating a change in learning or attention.

### Attendance interpretation

A track earns at most 1.5 sampling intervals of presence credit between matched detections; long gaps cause a new track. A track qualifies once the accumulated **estimated observed time** reaches the threshold. The default is 10 seconds, a short setting chosen for prototyping rather than a recommended institutional policy. Tracking may swap or split IDs, double-count people, or miss them entirely. No facial recognition or automatic student identification is performed. A roster member is only automatically marked present after a qualified track has been **manually matched** to that person. Unmarked is not the same as absent; all records should be checked by a person.

For recorded video, elapsed timestamps are relative to playback and the exported absolute timestamp is computed from the processing session's start—not the recording's original capture time.

## Privacy, limitations and responsible use

- Obtain informed permission and follow applicable institutional, legal, accessibility and child-protection policies **before** processing anyone's camera or microphone data. The consent checkbox is a reminder; it does not collect or verify individual consent.
- The demo data and synthetic test clip are clearly labeled. No real student attendance data is included.
- The local JSON store and CSV exports are **not encrypted**. The prototype has no login, role-based access, audit controls, retention scheduling, secure deletion, bias validation, or multi-user protection. Limit access to the machine, secure exports, and do not expose this server publicly.
- Delete an individual session from **Sessions**. To delete all stored data, stop the server and remove `data/sessions.json` (and any exports). A new fictional demo is created on the next start. You can choose a different data directory with `python app.py --data-dir /path/to/folder` or the `ATTENDANCE_DATA_DIR` environment variable. Filesystem or backup copies may persist after deletion.
- The face detector works best with clear, frontal faces and can perform poorly for distant or occluded faces; full-body HOG is best suited to upright, sufficiently large bodies. Neither is a reliable classroom attendance system.
- Audio is energy, not verified speech or participation; a silent or missing track can look the same for a video file. Audio is optional. Frame sampling and movement estimates can vary with browser, lighting, processing speed and camera movement.
- Approximate 2D tilt is based on a detected pair of eyes and is not a general head-pose model. The prototype does not infer emotions, concentration, personality, grades, or learning outcomes.
- Suggestions are advisory and should be interpreted with educators' and learners' context, not treated as factual assessments.

## Project structure

```text
app.py                 Standard-library HTTP server, local API, CSV export
engine.py              OpenCV detection, anonymous tracking, signal fusion and rules
store.py               JSON persistence and fictional demo fixture
static/                Offline web app, bundled fonts, illustration and synthetic clip
tests/                 Python unit and API tests
requirements.txt       OpenCV and NumPy
```
